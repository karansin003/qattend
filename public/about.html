About QAttend

Track. Alert. Stay Updated.

An independent student project built to simplify attendance tracking, academic deadline awareness, and exam qualification.

What QAttend Is

QAttend is an automated academic companion and attendance monitoring platform designed specifically for students accessing university records through the QUMS portal. It bridges student accounts with a high-reliability notification engine that delivers timetable updates, real-time attendance marks, backdated register modifications, and assignment reminders directly to each student's personal Telegram chat.

Rather than attempting to replace or duplicate university infrastructure, QAttend serves as a dependable notification layer. The university's official portal remains the sole authoritative source of truth; QAttend continuously checks for changes on your behalf so that you never miss crucial academic developments.

The Problem It Solves

Under standard university academic regulations, students are required to maintain a strict minimum threshold of 75% attendance across every individual course to qualify for end-of-semester examinations. In practice, tracking this requirement manually is burdened by several everyday challenges:

  • Unpredictable Marking Times: Instructors frequently submit attendance records in late afternoon batches, evening sessions, or days after a lecture occurred.
  • Retroactive Register Adjustments: Attendance corrections or backdated entries for earlier dates often go completely unnoticed unless a student manually reviews historical dates one by one.
  • Silent Coursework Publications: New practical assignments and theoretical assessments often appear on the portal without any push alert or email broadcast.
  • Complex Catch-Up Math: Understanding how many consecutive lectures must be attended to recover from a dip below 75% requires non-intuitive mathematical inequalities that are prone to calculation errors.

Project Origins & History

QAttend was created in early 2024 as an independent educational utility by Karan Kumar, a computer science student. Like many peers, Karan experienced the persistent friction of having to repeatedly solve CAPTCHA logins and refresh the university portal multiple times a day merely to verify if a morning lecture had been recorded.

What began as a focused terminal script to alert its creator about retroactive attendance adjustments evolved into a full-fledged, multi-user web platform. Today, QAttend provides isolated background monitoring, encrypted credential storage, automated Telegram alerts, and an interactive mathematical calculation engine for college students.

Technical Architecture & Engineering Stack

QAttend is built using a modern, lightweight, and resilient open-source technology stack:

  • Backend Runtime: Node.js (v20+) running Express.js for low-latency HTTP request processing, RESTful API routing, and security middleware.
  • Authentication & Identity: Google Firebase Authentication for industry-standard account management, secure password storage, and verified token authentication.
  • Relational Database: PostgreSQL (hosted on Supabase) utilizing strict relational integrity, indexed foreign keys, and multi-tenant data schemas, with a zero-dependency JSON fallback engine for local offline testing.
  • Headless Browser Engine: Playwright Chromium running in isolated headless containers to bridge university CAPTCHA authentication without fragile screen scraping or insecure OCR solvers.
  • Cryptographic Security: AES-256-GCM authenticated encryption with unique initialization vectors (IVs) to safeguard stored university credentials at rest.
  • Messaging Automation: Official Telegram Bot API (via node-telegram-bot-api) featuring isolated chat bindings, automatic message pruning, and state-deduplication to ensure zero duplicate alerts.

Core Product Principles

  • Facts Over Hype: Every capability documented on this website is functional and verified in production code.
  • Zero Credential Disclosure: University passwords are encrypted using AES-256-GCM and never exposed to other students, public pages, or Telegram messages.
  • Multi-Tenant Data Isolation: Every student account retains a strictly isolated database row, private session file (permissions 0600), and individual Telegram chat binding.
  • Noise Elimination: Background polling loops implement strict idempotency keys so that server restarts never trigger duplicate alert storms.
  • Full Student Control: Users retain absolute autonomy to connect, reconnect, disconnect Telegram, or permanently erase university credentials at any time.
